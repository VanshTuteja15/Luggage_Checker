## Goal (one paragraph, user-visible outcome)

Under the search bar, chips show what the search understood: "Samsonite", "Medium", "Spinner", "Hard shell", "Under $300", "At Amazon.ca", "In stock", "Black". Each chip can be removed (×), which runs the search again without that part. The page address carries the search (`/search?q=…`), so a search can be shared and the back button works. The parser already reads all of these from the typed text (eval: 68/68 queries all fields right); this task only shows and edits them.

## Contract (types/endpoints to use; do not change them)

- Chips come from `research.state.answer?.parsed` when the answer is back, else from `luggagePack.parseQuery(query)` (browser-safe; the catalogue vocabulary isn't in the browser bundle, so a catalogue-only brand may appear only once the answer is back).
- Fields: `brand`, `sizeClass` (label via `SIZE_LABELS`), `inches` ('23"'), `type`, `shell` ("Hard shell" / "Soft shell"), `material`, `colour`, `minPrice` / `maxPrice` ("$200 – $300", "Under $300", "Over $200"), `storeIds` (store names from the registry list the Settings page already loads), `inStock`, `sort` ("Cheapest first").
- Removing a chip = remove its words from the query text and search again. Keep a small, tested mapping from chip to the words to remove (e.g. "under $300", "between 200 and 300", "at amazon"); when a chip's words can't be found in the text, rebuild the query from the remaining fields instead of guessing.

## Requirements (numbered, testable)

1. Chips appear only after a search; product-line words are not chips (they are the product).
2. Each chip is a button with the accessible name "Remove {chip}"; focus moves to the search box after a removal.
3. `/search?q=samsonite+carry-on+under+%24300` opens and runs that search; each new search updates `?q=` (push for a new search, replace for a chip removal).
4. 375 px: chips wrap, no horizontal scroll; dark mode AA.
