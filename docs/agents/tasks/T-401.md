## Goal (one paragraph, user-visible outcome)

On a product page, under each store's price, the person sees what that store itself states about the product: a current promotion ("Sale $279.99, was $440.00"), and the specs on file (dimensions, capacity, weight, wheels, expandable). Each line says which store said it, how we read it, and when. Nothing is shown when there is nothing on file. Plain text only: no charts, no badges that look like our own claims.

## Contract (types/endpoints to use; do not change them)

- `GET /api/engine/offer-facts?url=<offer url>&url=…` (1–20 https URLs, signed-in) → `{ facts: OfferFacts[] }`, in the same order as the URLs (duplicates removed):
  - `OfferFacts = { url, sourceId: string | null, listingId: string | null, promotions: PromotionRecord[], attributes: Record<string, StoredAttribute> }`
  - `PromotionRecord`: `kind` (`percent_off | amount_off | sale_price | free_shipping | gift | code`), `method` (`compare_at | jsonld | page_text`), `percentOff`, `upTo`, `amountOff`, `salePrice`, `wasPrice`, `threshold`, `code`, `endsText` (verbatim), `endsAt` (approximate ISO), `evidence: string[]`, `firstSeenAt`, `lastSeenAt`
  - `StoredAttribute`: `{ value, method: "jsonld" | "rules" | "ai", evidence, confidence, sourceId, url, firstReadAt }`; keys `dimsCm` ([h, w, d] cm), `capacityL`, `weightKg`, `wheels` (2 | 4), `expandable` (true only)
- 400 = bad links; any other failure: hide the section (never an error on the page).

## Requirements (numbered, testable)

1. One request per page load with every offer URL on the page (≤ 20); no request when there are none.
2. Promotion line, per offer, only for `promotions` returned:
   - `sale_price` / `percent_off` / `amount_off`: "Sale $279.99, was $440.00" (CAD, 2 decimals). Add "20% off" only when `percentOff` is given (never compute one). "Up to" when `upTo`.
   - `free_shipping`: "Free shipping over $100" (or "Free shipping" without a threshold). `gift`: "Free gift". `code`: "Code SAVE20".
   - Then the source in muted text: "stated by {retailer} · {method label} · seen {lastSeenAt as 'Oct 30'}". Method labels: compare_at → "store's compare-at price", jsonld → "store's product data", page_text → "store's page text".
   - When `endsText` is set: "ends {endsText}" verbatim, with `endsAt` as a tooltip/title "about {local date}".
3. Specs line, per offer, only for attributes present: "55 × 40 × 20 cm · 40 L · 2.9 kg · 4 wheels · expandable", then muted "from {retailer} {method label: jsonld → 'product data', rules → 'product description', ai → 'description (AI read, checked)'} · read {firstReadAt as 'Oct 30'}". Units exactly as stored (cm, L, kg); no conversions in the UI.
4. Never show a promotion's figures as the offer's price; the existing price cell stays the only price.
5. Works at 375 px (wraps under the offer, no horizontal scroll) and in dark mode; text is selectable; links unchanged.
6. Loading: nothing is shown until the answer arrives (no spinner, no layout jump beyond the added lines).
