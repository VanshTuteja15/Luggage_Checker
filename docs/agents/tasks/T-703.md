## Goal (one paragraph, user-visible outcome)

Under the results, small sections help the next step: "Other sizes in this line" (the carry-on and large of the bag found, with prices), "Cheaper alternatives" (same size and type, a real lower price, with the saving: "$35.00 less"), and "Also comes in" (colours). Every price shows its label ("Verified live · 9:02 a.m." / "Last seen · Nov 20"), and pressing a product name searches for it. The data comes from our own index (never a web estimate); the minimal version already renders.

## Contract (types/endpoints to use; do not change them)

- `answer.suggestions?: AnswerSuggestions` = `{ otherSizes: SuggestedProduct[]; cheaper: SuggestedProduct[]; colours: string[]; didYouMean: string | null }`; absent when the index took longer than 400 ms (render nothing then).
- `SuggestedProduct` = `{ productId, name, sizeClass, price, retailer, url, label, saving }`; show `label` exactly as given; `saving` only on cheaper alternatives.
- `onSearch?: (q: string) => void` from `ResearchResults`.

## Requirements (numbered, testable)

1. Show the sections only when the search is done and they have items; never an empty heading.
2. Each item: name (a button calling `onSearch(name)`), size label (`SIZE_LABELS`), price (`usd`), store (link to `url`, new tab, `rel="noopener noreferrer"`), the label in the `FreshnessBadge` style for its kind ("Last seen" labels in the muted style).
3. Cheaper alternatives show "{saving} less" next to the price.
4. Colours as plain text chips (no swatches unless the name maps to the existing colour list; never a guessed colour).
5. Desktop: two columns (sizes | cheaper), colours full width; 375 px: one column, no horizontal scroll.
6. Headings are `h2` in the results' heading order; lists are `ul`.
